# AI contributor instructions

## Project facts

- This is a zero-runtime-dependency TypeScript library for browser menus. Keep runtime code on the existing TypeScript and DOM platform; do not add a dependency for a small helper.
- Source of truth is `src/`. `dist/` is generated by the build and must not be edited by hand.
- Public exports live in `src/index.ts`; public option and event types live in `src/types.ts`. Preserve existing API behavior unless the task calls for a change.
- Main code areas: `src/core/` (radial menu), `src/dom/` (rendering and triggers), `src/dropdown/` (dropdown and submenus), and `src/utils/` (shared helpers).
- See `docs/ARCHITECTURE.md` for layer boundaries and `CONTRIBUTING.md` for contributor workflow.

## Change rules

- Read the touched code and its callers before editing. Keep the diff limited to the requested behavior and preserve unrelated work in the worktree and index.
- Follow nearby TypeScript and Biome conventions. Keep strict types; avoid introducing `any` in production code.
- Keep pointer coordinates and `getBoundingClientRect()` values in viewport coordinates. Pair document listeners, timers, animation frames, and observers with cleanup in the existing lifecycle.
- Keep menu labels as text. Sanitize any HTML or SVG icon markup through `src/utils/sanitize.ts` before inserting it.
- Preserve keyboard behavior, focus handling, and ARIA semantics when changing menu interactions.
- Update relevant tests, docs, and `examples/vanilla/` when a behavior or public API changes. The static demo and docs are deployed from that directory.
- When preparing a release, keep `package.json`, `VERSION` in `src/index.ts`, `CHANGELOG.md`, and the demo version label aligned. Do not publish unless asked.
- For browser features or compatibility claims that may have changed, check current authoritative documentation instead of relying on memory.

## Checks

Use the project scripts as relevant to the change:

```sh
bun test
bun run type-check
bun run lint:check
bun run build
```

Prefer `lint:check` for validation because `lint` rewrites files. For DOM interaction changes, report whether browser behavior was actually exercised; unit tests alone do not verify pointer behavior in a browser.
